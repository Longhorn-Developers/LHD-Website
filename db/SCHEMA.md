# Database schema

This schema is for a fresh PostgreSQL database used by the membership portal.
The `users` table holds account and executive information; `teams` holds the
club's teams; `team_members` holds each user's team-specific role and lead
status.

The definitions below reflect the columns and values shown by the current
`SELECT *` results. For an existing database, do not recreate the tables;
follow the migration notes at the end instead.

## Tables

### `users`

```sql
CREATE TABLE users (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name TEXT NOT NULL,
    "userID" UUID NOT NULL DEFAULT gen_random_uuid(),
    "memberID" UUID DEFAULT gen_random_uuid(),
    email TEXT NOT NULL,
    password TEXT NOT NULL,
    team TEXT,
    role TEXT,
    "isLead" BOOLEAN NOT NULL DEFAULT FALSE,
    "isExec" BOOLEAN NOT NULL DEFAULT FALSE,
    "execRole" TEXT,
    "githubID" TEXT,
    "discordID" TEXT,
    status TEXT NOT NULL DEFAULT 'active',
    "dateJoined" DATE,
    "dateLeft" DATE,
    "createdAt" TIMESTAMP NOT NULL DEFAULT NOW(),
    reset_token TEXT,
    reset_token_expires TIMESTAMPTZ
);

CREATE UNIQUE INDEX users_user_id_uidx ON users ("userID");
CREATE UNIQUE INDEX users_member_id_uidx ON users ("memberID");
CREATE UNIQUE INDEX users_email_lower_uidx ON users (LOWER(email));
```

`team`, `role`, and `isLead` are retained for compatibility with existing user
records and the membership backfill. New membership data is stored in
`team_members`.

### `teams`

```sql
CREATE TABLE teams (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name TEXT NOT NULL,
    description TEXT NOT NULL DEFAULT '',
    createdat TIMESTAMP NOT NULL DEFAULT NOW(),
    updatedat TIMESTAMP NOT NULL DEFAULT NOW()
);

CREATE UNIQUE INDEX teams_slug_uidx
    ON teams (
        regexp_replace(LOWER(BTRIM(name)), '[^a-z0-9]+', '-', 'g')
    );
```

### `team_members`

```sql
CREATE TABLE team_members (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    team_id INTEGER NOT NULL REFERENCES teams(id) ON DELETE CASCADE,
    role TEXT NOT NULL,
    islead BOOLEAN NOT NULL DEFAULT FALSE,
    memberid UUID NOT NULL REFERENCES users("memberID") ON DELETE CASCADE,
    status TEXT NOT NULL DEFAULT 'active',
    datejoined TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    dateleft TIMESTAMPTZ,
    CONSTRAINT team_members_user_team_uidx UNIQUE (user_id, team_id)
);

CREATE INDEX team_members_active_by_team_idx
    ON team_members (team_id)
    WHERE dateleft IS NULL;
```

`user_id` references the internal numeric `users.id`; `memberid` keeps the
corresponding public `users."memberID"` identifier.

## Applying the migrations

For a fresh database, create the tables above. If you are carrying over
membership values from the legacy `users.team` column, run migration `002`:

```sh
psql "$DATABASE_URL" -f db/migrations/002_normalize_team_memberships.sql
```

Migration `001` is for existing installations whose `users` table predates
these profile columns. It backfills `memberID` and `dateJoined` and makes both
required, so it does not preserve the nullable values shown in the current
database output.

Migration `002` creates team rows for existing `users.team` values and copies
those assignments into `team_members`. The development team defaults are
seeded by the application only in development mode.
